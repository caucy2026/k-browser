# Microsoft Office 版式文档兼容性策略

## 当前决策：屏蔽浏览器内阅读

双屏浏览器的本地文档阅读器只适合语义文档：正文、表格、代码和电子书。PowerPoint（`.ppt`、`.pptx`、`.pptm`、`.potx`、`.potm`、`.pps`、`.ppsx`、`.ppsm`）、Word（`.doc`、`.docx`、`.docm`、`.dotx`、`.dotm`）和 Excel（`.xls`、`.xlsx`、`.xlsm`、`.xltx`、`.xltm`）均为版式文档；可读结果必须同时保留分页、图像、字体、主题、形状、层级、裁切和表格/公式状态。

此前实现仅抽取 PPTX 内的文本节点（`a:t`）、DOCX 的段落和 XLSX 的单元格值。这会丢弃图片、分页、页眉页脚、字体、公式展示、合并单元格与版式，把原始文件错误显示为连续文字或无样式表格。以 `KEMI-S1-KEYNOTE.pptx` 验证：该文件有 18 页，混用全页图片、深浅主题、图文卡片和多列布局；文本提取无法保持任何可接受的阅读效果。

因此本版本不再把 Microsoft Office 版式文档声明为浏览器内可读格式：

- 从 Android 的 `ACTION_VIEW` 演示文稿 MIME 声明中移除，避免在“用什么应用打开”中误导用户；
- 即使文件以通用 MIME 或手工打开进入阅读器，也显示阻止页，绝不降级为纯文本；
- 阻止页明确说明原因，并承诺文件不上传网络、不执行宏或脚本。

## 恢复支持的门槛

只有满足以下条件才恢复该格式，而不是重新启用文本抽取：

1. 使用真实的逐页/逐页纸 PowerPoint、Word 和 Excel 渲染器，输出应与原文件视觉一致；
2. 离线渲染，受输入、内存与解压大小限制，禁止运行宏、外部链接和脚本；
3. 支持页缩略图、翻页、缩放与双屏连续阅读；
4. 用包含图片、表格、主题、形状、多列和中文字体的样本逐页比对；
5. 真机验证冷启动、横竖屏、双屏进入/退出和连续十页翻页。

在这些条件具备前，推荐由专用演示文稿应用处理 PPT/PPTX，浏览器继续承担网页和已验证的语义文档阅读。
