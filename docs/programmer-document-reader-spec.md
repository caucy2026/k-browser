# KEMI 双屏浏览器文档阅读兼容规范

## 1. 目标与“支持”的定义

文档格式只有同时满足以下条件，才标记为“支持”：

1. 可由文件管理器的“打开方式”进入双屏浏览器；
2. 内容在同一个 `1920 × 2560` 逻辑页面中排版，Display 2 显示上半区，Display 0 显示相邻下半区；
3. 任意一屏滚动时，两屏作为一个页面连续移动，不镜像、不反馈抖动；
4. 可选择和复制文本，并可从 Display 2 当前可见首行开始朗读；
5. 任意一屏返回或退出时，两屏会话同步结束；
6. 无网络转换、无广告、无账号注册提示，不把本地文档上传到第三方服务。

只完成下载、调用其他应用或显示空白页，不算支持。

## 2. 格式分级

### A 级：结构化阅读

保留标题、段落、列表、代码块和表格等主要语义，适合双屏阅读与朗读。

| 类别 | 扩展名/格式 | 处理规则 |
| --- | --- | --- |
| 文本与源码 | `txt`, `log`, `md`, `markdown`, `java`, `kt`, `kts`, `c`, `h`, `cpp`, `hpp`, `go`, `rs`, `py`, `js`, `jsx`, `ts`, `tsx`, `css`, `scss`, `sh`, `bash`, `zsh`, `bat`, `ps1`, `sql`, `graphql` | UTF-8 优先，BOM/GB18030 兼容；源码按等宽、保留空白显示 |
| 配置与接口 | `json`, `xml`, `yaml`, `yml`, `toml`, `ini`, `conf`, `properties`, OpenAPI | JSON/XML 格式化；其余保留结构；OpenAPI 按 JSON/YAML 文本阅读 |
| 表格文本 | `csv`, `tsv` | 按 RFC 4180 兼容规则解析引号、逗号、换行并生成可滚动表格 |
| 网页文档 | `html`, `htm`, `xhtml` | 本地离线加载；禁止主动执行不可信脚本 |
| 现代 Office | `docx`, `xlsx`, `pptx` | 离线解析 OOXML ZIP 包；提取正文、工作表、幻灯片文字和表格 |
| 开放文档 | `odt`, `ods`, `odp` | 离线解析 ODF 1.3 包中的 `content.xml` |
| 电子书 | `epub` | 按 EPUB 3.3 的 container/package/spine 顺序合并章节 |
| 富文本 | `rtf` | 解析段落、Unicode 和常用转义，忽略不影响正文的控制组 |
| 电子书兼容 | `mobi`, `azw` | 支持未加密 PalmDOC/MOBI 正文；加密文件明确提示不支持 DRM，不静默失败 |
| 图表源码 | `mmd`, `mermaid`, `puml`, `plantuml` | 安全显示和朗读源文件；不调用外部在线渲染服务 |

### B 级：原生查看或兼容提取

| 类别 | 格式 | 能力边界 |
| --- | --- | --- |
| PDF | `pdf` | 使用 Gecko 内置 PDF 查看器显示、缩放、搜索；文本型 PDF 可选择/复制，扫描型 PDF 不承诺 OCR |
| 旧版 Office | `doc`, `xls`, `ppt` | 提供可打印字符串兼容视图和明确提示；复杂布局、公式、宏不承诺还原 |

### 明确不执行的内容

- Office 宏、ActiveX、嵌入式可执行文件；
- EPUB/HTML 内联脚本和远程跟踪代码；
- 加密 Office、DRM 电子书的绕过或解密；
- 扫描图片 OCR（没有可靠离线 OCR 引擎时不得伪报成功）；
- Mermaid/PlantUML 的第三方在线渲染。

## 3. 规范依据

- Markdown：CommonMark 0.31.2；
- JSON：RFC 8259；
- CSV：RFC 4180，并兼容常见 UTF-8 BOM；
- OpenAPI：OpenAPI 3.0/3.1/3.2 的 JSON 或 YAML 文档；
- EPUB：W3C EPUB 3.3，按 spine 确定阅读顺序；
- ODF：OASIS OpenDocument 1.3；
- OOXML：ECMA-376/ISO/IEC 29500 包结构，只读取正文相关 XML。

## 4. 车机安全与性能边界

| 项目 | 上限/策略 |
| --- | --- |
| 普通文件输入 | 32 MiB；超过时给出可理解提示 |
| ZIP 条目数 | 2,048 个 |
| 单个解压条目 | 16 MiB |
| 累计解压数据 | 64 MiB，防 ZIP bomb |
| 生成阅读 HTML | 16 MiB 或 500,000 个可读字符，达到上限显示“内容已截断” |
| 表格 | 每表最多 5,000 行、128 列 |
| 解析线程 | 后台单线程，不阻塞 Android 主线程 |
| 缓存 | 仅应用私有 cache；按容量/时间清理；不记录文档正文到日志 |
| 网络 | 本地文档解析全程离线；文档中的远程资源默认不主动加载 |
| 日志 | 只记录格式、字节数、字符数、耗时和错误类型 |

## 5. 双屏排版规则

- 逻辑画布固定为 `1920 × 2560 @ 60 Hz`，双屏模式禁止旋转；
- Display 2 是阅读顺序的第一屏，Display 0 是紧接其后的第二屏；
- 文档 HTML 使用响应式正文宽度、较大行高、等宽代码、粘性表头和高对比配色；
- 只创建一个 GeckoSession 和一套滚动状态，禁止用两个独立 WebView/会话互相同步；
- 单屏快捷模式复用相同文档内容与主页，仅输出一个 1920 × 1280 视口。

### 内部页面来源

解析结果先写入应用私有 `cache/kbrowser-documents`，再由只绑定 `127.0.0.1` 的进程内只读服务提供给
Gecko。该服务不能从局域网访问、不接受上传、不列目录，并要求不可猜的缓存文件令牌。采用普通 HTTP
origin 而不是 `data:` 的原因，是让内置朗读 WebExtension 仍能定位 D2 当前可见首行、逐段高亮和自动滚动；
这不属于远程转换或文档上传。

## 6. 验收判定

每个格式至少使用一个包含唯一顶部标记、跨屏接缝标记、可复制文本、中文、英文和长段落的样例。结果必须同时记录：

- 打开结果和识别格式；
- D2/D0 截图与 Activity/Display 状态；
- D2、D0 各一次滚动后的连续性；
- 选择复制和朗读起点；
- 冷启动解析耗时、PSS 内存增量、崩溃/ANR；
- 返回/退出后的双屏 Activity 清理结果。
